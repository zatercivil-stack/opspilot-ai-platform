# Оценка качества обработки

60 вручную размеченных синтетических обращений и 12 текстовых счетов. Включены неоднозначность, отрицание, инструкция внутри входного текста, английский финансовый запрос и неподдерживаемая подпись итоговой суммы. Это небольшой набор разработки, не независимый benchmark и не клиентские данные.

Здесь опубликованы входные примеры и отчёты. Полный evaluation runner входит в приватную реализацию; приведённые JSON не являются доказательством независимого production-бенчмарка. На собеседовании можно разобрать ошибочные случаи, разметку и методику.

Отдельно можно запустить [пример независимого контроля](../samples/review_policy.py) без ключей и БД:

```bash
python3 samples/review_policy.py
```

Он показывает, почему финансовый текст или обмен всё равно отправляется сотруднику при ошибочной категории модели. Это четыре локальные проверки политики, не запуск полного классификатора.

## Измеренный LOCAL

Отчёты: [исходный](reports/local-baseline.json) и [после исправления правила обмена](reports/local.json).

| Метрика | Результат |
| --- | --- |
| Верная категория | 54/60 — 90% |
| Ошибки выполнения классификатора | 0/60 |
| Обязательная проверка человеком | Исходно 23/24; после исправления 24/24 |
| Доля обращений с ручной проверкой | 24/60 — 40% |
| Валидные структуры счёта | 10/12 |
| Верные размеченные поля счёта | 58/60 — 96,67% |

Исходная оценка обнаружила пропуск обмена при категории `order`; правило дополнено и закреплено тестом. Повторная оценка использует ту же выборку, поэтому 24/24 не доказывает качество на новых данных. Два счёта с подписью «Общая сумма» остаются отрицательными примерами: нельзя скрывать их исключением из знаменателя.

Файл JSON содержит результаты каждого случая, precision/recall по категориям, хеши данных и длительности. Латентность LOCAL — время вызова правил в контейнере, не сетевой SLA системы. `confidence` модели не используется как измеренная точность.

## LIVE: подготовлено, не измерено

LIVE-качество и полная стоимость не измерены. В приватном runner предусмотрены явный выбор LIVE, отказ без ключа, запись модели, версии промпта, ошибок, latency и provider usage. Стоимость берётся только из ответа провайдера; отсутствие данных не заменяется оценкой.

Следующий этап: новая слепая выборка с независимой разметкой, разбор ложных направлений на ручную проверку и пропусков, повторные LIVE-прогоны и сопоставление стоимости с качеством.
